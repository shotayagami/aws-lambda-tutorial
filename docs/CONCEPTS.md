# Step 0: Lambda の概念

## 1. Lambda とは

**イベントが来たときだけコードを実行する、サーバーレスのコンピュートサービス**。
サーバーの OS・パッチ・スケールは AWS 任せで、利用者は「関数」と「設定」だけを用意します。

## 2. 基本用語

| 用語 | 意味 |
|------|------|
| 関数 (Function) | デプロイ単位。コード + 設定(メモリ、タイムアウト、環境変数、IAM ロール) |
| ハンドラ (Handler) | エントリポイント。`ファイル名.関数名`(例: `todo_api.app.handler`) |
| イベント (event) | 呼び出し元が渡す JSON。トリガーごとに形が違う |
| コンテキスト (context) | 関数名・リクエスト ID・残り時間など実行時情報 |
| ランタイム | 実行言語環境(python3.13, nodejs22.x など) |
| トリガー | 関数を呼ぶもの(API Gateway, S3, SQS, EventBridge など) |
| 実行ロール | 関数が持つ IAM ロール。**関数が AWS を操作する権限はここで決まる** |
| レイヤー | 共有ライブラリなどを別パッケージにして複数関数で使い回す仕組み |

## 3. 実行モデル(最重要)

```
[コールド スタート]                          [ウォーム]
 実行環境を作成 → コード取得 → Init           すでにある実行環境を再利用
 (グローバル領域を実行)      → handler 実行   → handler 実行のみ
```

- **Init フェーズ**(グローバル領域)はコールド スタート時に 1 回だけ。DB クライアントなどはここで作って再利用する
- 1 つの実行環境が**同時に処理するリクエストは 1 つ**。同時リクエストが増えると環境が増える(= 自動スケール)
- 環境はいつ破棄されるか分からない。**メモリやローカルファイルを永続データとして頼らない**(`/tmp` は最大 10GB の一時領域)
- コールド スタートの目安は Python で数百 ms 程度。パッケージが大きい・VPC 接続・メモリが小さいと伸びやすい

## 4. 課金と制限(主な値。最新は公式で確認)

- 課金: **呼び出し回数 + 実行時間 (GB 秒)**。無料枠あり
- メモリ: 128MB〜10,240MB(CPU はメモリに比例)
- タイムアウト: 最大 **15 分**(既定 3 秒)
- ペイロード: 同期呼び出しで 6MB まで
- 同時実行数: アカウント/リージョンごとの上限あり(引き上げ申請可)

→ 長時間処理・常駐接続(WebSocket 自前保持など)・大容量レスポンスは別手段を検討。

## 5. 呼び出し方式

| 方式 | 例 | 特徴 |
|------|----|------|
| 同期 | API Gateway, Function URL | 結果を待つ。エラーは呼び出し元に返る |
| 非同期 | S3, EventBridge, SNS | 投げっぱなし。失敗時は自動リトライ(既定 2 回)、DLQ/送信先設定が重要 |
| ポーリング | SQS, Kinesis, DynamoDB Streams | Lambda 側がキューを読みに行く。バッチ処理 |

## 6. 権限(IAM)の考え方

- **誰が関数を呼べるか**: リソースベースポリシー(例: API Gateway からの呼び出しを許可)
- **関数が何を操作できるか**: 実行ロール(例: 特定の DynamoDB テーブルの読み書きのみ)
- 最小権限にする。SAM なら `Policies: - DynamoDBCrudPolicy:` のように対象を絞る

## 7. 向いている / 向いていない

| 向いている | 向いていない |
|-----------|-------------|
| 呼び出しが不定期・波がある API | 常時高負荷で一定のトラフィック(コンテナ/EC2 が安いことも) |
| イベント駆動の小さな処理(画像変換、通知) | 15 分を超える処理 |
| 運用負荷を下げたい小〜中規模 Web API | 低レイテンシが厳密に必要で、コールド スタートが許されない |

## 8. 運用の入口

- ログ: `print` / `logging` の出力は自動で **CloudWatch Logs** へ
- メトリクス: Invocations / Errors / Duration / Throttles が CloudWatch に自動出力
- 設定で効くもの: メモリ(増やすと速くなり、結果的に安くなることもある)、タイムアウト、同時実行数の予約
- 性能面: 冪等に作る(非同期はリトライされる)、Init で重い処理をしすぎない
